## Success gates

- **G1 — the theory is right, not merely non-crashing.** Cases asserted with expected values:
  same key → unison/compatible; A minor ↔ C major → **relative** (compatible); parallel
  minor/major → same root, flagged as a mode shift; roots a **tritone** apart (6 semitones) or a
  semitone apart → flagged as conflicting; a perfect fifth apart → consonant. The verdict must
  come from the **pitch-class overlap** of the two modes (via `scaleIntervals`), not just the root
  interval — that is the whole point.
- **G2 — defaults to the project's current key** when no candidate key is given (reads `get_scale`).
- **G3 — accepts the shapes the rest of the surface already produces:** a human key string
  ("F minor"), or `root` + `scaleMode` ints, or a `scaleType` from `analyze_midi_file`. Unparsed /
  "unknown" input returns a clear "cannot determine the candidate's key" error rather than a
  confident wrong answer.
- **G4 — parity.** MCP `key_check` ↔ RPC composition twin, same argument keys, same failure text.
- **G5 — it is wired into the workflow** (docs): the palette/sound-selector step references
  `key_check` as the pre-listen gate, and the tool's description says what it is for.
